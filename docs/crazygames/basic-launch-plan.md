# CrazyGames: план доработок для Basic Launch

Цель — подать игру на CrazyGames в режиме Basic Launch (без SDK и рекламы) так, чтобы:
- игра прошла QA (technical + gameplay requirements);
- метрики Basic Launch были как можно лучше: конверсия ≥1 минуты игры 80%+, среднее время 10+ минут, D1 retention 10–15%;
- GitHub Pages и пакет для Project 0 продолжали работать из того же `main`;
- SDK CrazyGames потом подключался в одном месте, без переделки игры.

Требования: <https://docs.crazygames.com/requirements/intro/>

## Архитектурный принцип

```
experience/          ядро игры (и пакет Project 0): правила, UI, звук. Знает только объект p0
web/p0web.js         веб-прослойка: p0 для браузера. Здесь живёт p0.web
web/platform.js      (новое) профиль платформы: 'pages' | 'crazygames' + хуки под будущий SDK
tools/build_cg.*     (новое) сборка dist/crazygames/ и zip для загрузки
```

- В `experience/` нельзя обращаться к `window`, SDK или CrazyGames напрямую, только через `p0` / `p0.web?.…`. В Project 0 `p0.web` нет, поэтому каждый вызов должен быть необязательным.
- Отличия платформ задаются профилем (флагами), а не ветками и не копиями файлов.
- Работа идёт в `main` через короткие ветки `cg/<задача>`, каждая задача — отдельный коммит или PR.

## Общие правила для каждой задачи

1. Перед чтением кода — `graphify query "<вопрос>"` (правило из CLAUDE.md). После правок — `graphify update .`.
2. Не ломать: GitHub Pages (`index.html`), Project 0 (`experience/` через `tools/harness.html`), онлайн-комнаты.
3. Проверка: dev-сервер `python tools/server.py 5500` (в `.claude/launch.json` он называется "dev"). Игра на `http://localhost:5500/`, харнесс на `tools/harness.html?room=T&name=Alice`, правила на `tools/simtest.html`. В консоли не должно быть ошибок.
4. Тексты в UI только на английском, все строки — в `experience/strings.js`.
5. Работать в ветке `cg/<slug>` от свежего `main`. В конце коммит в эту ветку, без пуша. Коротко отчитаться: что изменено, что проверено, что не проверено.

### Задача 1. Профиль платформы и хуки под SDK

```text
Задача 1 из docs/crazygames/basic-launch-plan.md: следуй «Общим правилам» оттуда.

Сделай слой платформы для веб-сборки, чтобы одна кодовая база работала на GitHub Pages и на CrazyGames, а SDK CrazyGames потом подключался в одном месте.

1. Создай web/platform.js. Он экспортирует профиль { id: 'pages' | 'crazygames', quickPrefix, allowLinks, ... }. Платформа определяется так: глобальная переменная, которую задаёт сборочный HTML (например window.CSL_PLATFORM), иначе параметр ?platform=crazygames для локальной проверки, иначе 'pages'.
2. В профиле заведи флаги для будущих задач: allowLinks (копирование/шаринг ссылки на комнату), quickPrefix (префикс комнат Quick Match, на pages оставить нынешний 'QM', чтобы не разорвать текущих игроков), privacyNotice.
3. Заведи объект хуков с пустыми реализациями (no-op) под будущий SDK: loadingStart/loadingStop, gameplayStart/gameplayStop, happytime, midgameAd(): Promise, mute/unmute (через флаг, который уважает App.playSound), getUser(): Promise<{name, avatar}|null>, inviteLink(code): string|null, roomChanged(info), locale(). Пока их никто не реализует, но сигнатуры и места вызова должны быть готовы.
4. Пробрось профиль и хуки в p0.web (web/p0web.js), например как p0.web.platform и p0.web.hooks. Вызови хуки в правильных местах: loading вокруг boot(); gameplayStart, когда начинается партия (startSolo, resumeSolo, старт shared-стола); gameplayStop при выходе в меню, открытии игрового меню, конце партии; хук «между партиями» (rematch / новая игра после конца партии) — сюда потом встанет midgame ad. В experience/ вызывать только через this.p0.web?.hooks?.x?.(), чтобы в Project 0 ничего не изменилось.
5. Сделай глобальный mute, который можно включить извне (для будущей рекламы), не трогая пользовательскую настройку звука.

Проверь, что GitHub Pages и харнесс Project 0 работают как раньше, а с ?platform=crazygames в консоли видно, какой профиль выбран, и вызовы хуков (временно через console.debug под флагом). Опиши в отчёте, где именно стоит каждый хук.
```



## После Basic Launch: подключение SDK

Всё подключается в web/platform.js через хуки из задачи 1, ядро игры не меняется.

Сделано (задача 12, multiplayer, <https://docs.crazygames.com/requirements/multiplayer/>):
- скрипт SDK v3 только в сборке crazygames (tools/build_cg.py; `?platform=crazygames` грузит его сам), `await SDK.init()` до старта игры с таймаутом 10 с; `environment` 'disabled' или SDK не загрузился — игра как на Basic Launch, комнаты по коду;
- `inviteLink({ roomId })` — кнопка Invite Link копирует ссылку SDK; `getInviteParam('roomId')` — игрок по ссылке сразу входит в комнату;
- `updateRoom({ roomId, isJoinable, inviteParams })` при входе в комнату и когда меняется, можно ли в неё войти (правило то же, что у net.js при входе: не полна, у quick-стола во время игры бот держит место), `leftRoom()` при выходе; старый SDK без updateRoom — `showInviteButton` / `hideInviteButton`;
- `isInstantMultiplayer`: без меню и First Match — в комнату из приглашения или в новую свою (режим и поле из настроек Online);
- `addJoinRoomListener`: выйти из текущей комнаты (соло-партия откладывается и возвращается после комнаты) и войти в новую;
- rematch в той же комнате, доступность комнаты обновляется после партии.

Осталось (не сейчас):
- `game.loadingStart/Stop`, `gameplayStart/Stop`, `happytime` (победа) — в уже расставленные хуки;
- midgame ad в хуке «между партиями», с глобальным mute и блокировкой ввода до `adFinished`/`adError`;
- rewarded ad — только если появится подходящая награда (например, лишняя карта в соло), не в онлайне;
- `user`: имя и аватар CrazyGames вместо поля имени (hooks.getUser), автологин;
- `data`: сохранения (settings, партия) через Data-модуль вместо localStorage, по тому же адаптеру;
- `locale` из system info — когда появятся переводы.
